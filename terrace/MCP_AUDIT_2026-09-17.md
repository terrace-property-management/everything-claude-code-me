# MCP connector audit — 2026-09-17

Follow-up to the adoption report's Track S item ("audit active MCP server
count per session against the under-10-active guidance" in
`terrace/mcp-servers.json`'s `_comments.context_warning`). The audit's real
finding changes that framing materially — recorded here, and the two files
it corrects (`terrace/mcp-servers.json`, the adoption report doc) have been
updated to point at this.

## The guidance doesn't transfer cleanly — here's why

`_comments.context_warning`'s "<10 MCPs" number comes from a Node/npm-era
Claude Code setup where every enabled MCP server's full tool schemas load
into every session's context up front — the mechanism that produces the
"200k context can shrink to 70k" collapse the original repo warns about.

This account's Claude Code CLI uses **deferred tool loading**: an MCP
server's tools appear in the system prompt as bare names (via `ToolSearch`),
and full schemas only load when a name is actually selected. The real
standing cost of an inactive server is its tool-name strings sitting in the
listing, not its schemas — bounded, on the order of low single-digit KB
across all 15 servers, not the collapse the warning describes.

There's also a **mechanism split** the original guidance doesn't
distinguish:

- **Project-scoped local servers** (`playwright`, `render`, `terrace-ops-v2`,
  `filesystem` — all configured account-wide in this account's `.claude.json`
  `mcpServers`, plus anything in `terrace/mcp-servers.json`) *can* be
  disabled per project via `disabledMcpjsonServers`. Checked: neither tracked
  project (`C:/Users/sward`, the OneDrive hub) uses this — both have an empty
  disabled list, so all four are enabled everywhere.
- **claude.ai account Connectors** (Gmail, Microsoft 365, Notion, Google
  Drive, Google Calendar, QuickBooks/Meridian, Neon, Docusign, Claude Docs,
  Context7) have **no per-project lever in Claude Code**. They're
  enabled/disabled at claude.ai Settings > Connectors, account-wide — a
  change there affects claude.ai web, mobile and Cowork too, not just this
  CLI session.

Ten of the fifteen active servers this session are in the second category.
"Audit and disable via project config" — the action the original Track S
item implied — simply cannot reach them.

## An important caveat on the zero-usage list

**Zero here means zero via this account's local Claude Code CLI transcripts
— not necessarily zero everywhere.** These four (Context7 connector, Google
Drive, Notion, Google Calendar) could still see real use through claude.ai
web chat or Cowork sessions, whose transcripts aren't stored in this local
`.claude/projects/` folder and so can't be measured from here. Several
`qcvp-*` skills describe Notion usage extensively (`notion-search`,
`notion-query-data-sources`, etc.), which is hard to square with zero real
calls anywhere in this dataset — either those workflows genuinely aren't
being run from this account today (plausible: existing memory already notes
`qcvp-daily-action-items`/`qcvp-ops-command-center` are "still
Notion-dependent," implying a pending migration off Notion), or they run
somewhere this measurement can't see. **Don't disable any claude.ai
Connector off this data alone — confirm with Spencer first**, since that
toggle is account-wide, not scoped to this one investigation.
